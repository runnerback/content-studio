title: Zero warnings on the directory scanner's own environment

- The community directory scans the repository without `@types/node` and without the gitignored build outputs. The remaining 227 warnings it still reported on 3.11.14 all came from that difference: `Buffer` / `require` (Node globals) and ES2019+ methods (`trimStart`, `flatMap`, `Object.fromEntries`, `Array.prototype.at`) resolved locally only because `@types/node` happened to bring them along.
- `tsconfig.json` now declares `lib: ES2022 + DOM` explicitly; `types/node-globals.d.ts` adds mergeable declarations for the Node globals the desktop-only code paths use; `tsconfig.scan.json` (`types: []`) makes the local scan and the release guard see exactly what the directory sees. Result on that environment: 0 problems.
- Transitive dependency `@xmldom/xmldom` (via mathjax → speech-rule-engine) pinned to 0.9.12 to clear the advisory shown on the directory.
- No functional changes.
